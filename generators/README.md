# generators

Pure functions per template, `(part, ctx) -> string`: `specimenName`, optional `specimens(parts, ctx)`, `microscopy`, `diagnosis`, optional `prepare(caseState)`, optional `summary(parts, ctx)` (appended after the diagnosis lines), optional `comment(parts, ctx)` (case-level text at the head of the COMMENT block, before the snippets and the typed comment), optional `derive(values, changedId)` (a patch of field values to apply after the user edits `changedId`; `src/engine.js` `applyDerived`, used by the HER2 DISH calculator), optional `macro(part, ctx)` (MACROSCOPIC DESCRIPTION block), optional `blockKey(part, ctx)` (BLOCK KEY block — Phase 4b benign resections, one `(A) (1) … (2) …` line per part), optional `intraop(parts, ctx)` (INTRAOPERATIVE CONSULTATION block placed before the microscopy; used by `frozen.js`) and optional `molecular(part, ctx)` (MOLECULAR FINDINGS block between the microscopy and the diagnosis, parts joined by a blank line; a biomarker report's result lines, used by `breast_ish.js`, whose diagnosis is then one line naming the specimen — `docs/specs/biomarker-report-layout.md`). Each part line begins `(${part.label}) `; the engine strips it for single-part cases.

`breast.js` appends the biomarker block from `breast_biomarkers.js`, a line-for-line port of the CancerReportingTemplate breast biomarkers page (`docs/breast-biomarkers-source.md`). Its option strings, output lines, pre-analytic thresholds, methodology sentences and comments are the source template's and are covered by `tests/breast.test.js`; the breast schema turns the britishiser off so they pass through unchanged.

`duodenal.js` derives the Marsh–Oberhuber type from villi, IELs and crypts (`marsh()`); `cervical.js` ranks squamous (`squamousRank`) and glandular (`glandularRank`) lesions per part and reads the case-level `cytology` field for the discordance comment. Both expose `summary()` for multi-part cases.
