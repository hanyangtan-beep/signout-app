# schemas

**Starting a new template?** Run `npm run new-template -- <id> --system <S> --kind <K> --name "<Name>" --label <Label> --organ <ORGAN>`. It writes the schema, generator, test and fixture directory with every required key already in place and rebuilds the manifest, then leaves a `TODO` at each decision it cannot make. The scaffold, the paired research brief and the curation rules are in `docs/new-template-brief.md`. Do not hand-write the boilerplate below from scratch.

One JSON file per template. Keys: `id`, `version`, `name`, `shortName`, `organ`, `specimenNoun`, `maxParts`, `defaultParts`, `generator`, `style`, `caseFields`, `options`, `partDefaults`, `fields`, `example`.

Field types: `text`, `textarea`, `number` (`min`, `step`, `suffix`), `checkbox`, `select` / `grade` (`options`, `optionLabels`, `optionsByField`, `optionGroups`, `showIf`, `defaultForFirstPart`), `multiselect` (array value; `options`, `exclusive: [option]` clears the others when ticked, `default: []`).

`optionGroups: [{ label, options }]` on a long select renders the list in `<optgroup>`s (Skin SCC tumour site: head and neck / trunk and limbs); the flat `options` stays the list that is validated and printed, and options no group names follow the groups. A grouped select also shows its `help` under the list; on other selects `help` is a schema note only.

`showIf: { field, is | not | truthy | min | max }` — for multiselect fields `is` means "contains any of", `not` "contains none of", `truthy` "at least one ticked", `min` / `max` count the ticked options.

Optional keys: `options[]` case-level switches (`{id, label, default}`; read by the generator through `ctx.options`); `presets[]` one-click part sets (`{id, label, help, caseTitle, parts: [{values}]}` — the Presets row in the case card replaces all parts, see the gastric Sydney protocol).

Templates: `gastric_biopsy`, `colonic_polyp`, `prostate_biopsy`, `ibd_biopsy`, `oesophageal_biopsy`, `frozen_section`, `breast_biopsy`, `duodenal_biopsy`, `cervical_biopsy`, `endometrial_biopsy`, `cervical_excision` (LEEP), `lung_biopsy`, and the Phase 4b benign resections `lymph_node`, `placenta`, `gallbladder`, `thyroid_benign`, `parathyroid`, `appendix`, `uterus_benign`, `ovarian_cyst`, `skin_cyst`, `skin_excision`, `breast_excision`, `turp`, `turbt`, `tonsils`, `soft_tissue_benign`, `nasal_polyps`, `skin_lesion`, `aortic_valve_aorta`, `stoma`, `liver_benign`, `jaw_cyst`, `salivary_benign`, the Phase 5 cancer resections `colon_resection`, `gist_resection` and `endometrial_carcinoma` (the endometrial schema is generated by `python3 scripts/gen-endometrium-schema.py` — edit the script, not the JSON), and the six cytology templates from `scripts/gen-cytology-schemas.py` (breast is generated by `node scripts/build-breast-schema.mjs`, which pulls the biomarker fields from `generators/breast_biomarkers.js` — edit the script, not the JSON).

Template metadata (Phase 4d, required — `scripts/build-manifest.mjs` refuses a schema without them): `system` (GI, Hepatobiliary, GU, Gynae, Breast, Thoracic, Head and neck, Skin, Cardiovascular, Lymphoid, Soft tissue, Endocrine, Frozen, Cytology), `kind` (`biopsy` / `benign resection` / `cancer resection` / `frozen` / `cytology`), `shortName` as "Organ · procedure" (`Cervix · LEEP / cone`), `label` (the short header word — never a bare procedure or lesion name such as "Biopsy" or "Polyp"), `rank` (header order within the Small biopsy row; lower = more frequent; default 100), `aliases` (palette search terms — abbreviations, eponyms, key findings). After editing metadata run `node scripts/build-manifest.mjs` (also done by `npm run build`); `tests/picker.test.js` fails if the committed manifest is stale. Optional: `snippets[]`, `options[]`, `presets[]`.

## Benign resections (Phase 4b)

Resection templates carry a **Macroscopy** field group (`"group": "Macroscopy"` on each consecutive macroscopic field — the part card renders them in one collapsible fieldset whose open/closed state is remembered) and two extra generator exports: `macro(part, ctx)` → the `(A) Received in formalin is a …` paragraph (MACROSCOPIC DESCRIPTION block) and `blockKey(part, ctx)` → one `(A) (1) Cystic duct margin. (2) Body. (3) Fundus.` line (BLOCK KEY block, printed after the macro and merged above the typed block key in the Google Doc). Both return `''` when the case option `macro` is off. The engine drops the `(A) ` prefix for single-part cases, so the printed block key matches the house `(1) … (2) …` form. Building conventions, wording rules and the test checklist are in `docs/phase4b-brief.md`.

## Cancer resections (Phase 5)

Synoptic / hybrid templates (`kind: cancer resection`) add to the benign-resection conventions:

- `source` — `{ template, url, capProtocol, staging, stagingProtocol }` records the QMH CancerReportingTemplate page the elements were taken from, the CAP protocol version and the AJCC edition. Start from `node tools/import-qmh.js <saved page.html>`; the draft lists the printed elements in the page's `updateDescription()` order with their options, and curation into house field ids / labels is by hand.
- Generator exports `synoptic(part, ctx)` → the `- Label: value` element list (SYNOPTIC REPORT block, printed after the narrative microscopy and before the diagnosis; for multi-part cases prefix a `(A) Specimen` heading line), `validate(part, ctx)` → `[{ level: 'error' | 'warn', message }]` shown in the Checks panel, and the usual `microscopy` / `diagnosis` / `macro` / `blockKey` / `flags`.
- Staging goes through `src/staging/index.js` — `deriveTNM(values, protocol)` with the rule table in `src/staging/<protocol>.js` (currently `colorectal`), `stageLine(result)` for the stage-group line. Field ids the protocol reads (`tumourExtension`, `nodesExamined`, `nodesPositive`, `tumourDeposits`, `distantMetastasis`, `treatmentEffect`, `multiplePrimary`, `recurrent`, `tnmOverride`, `tnmOverrideReason`) must use the option strings the table expects; add a `tests/staging.test.js` block for every new protocol.
- Case options `synopticOnly` (omit the narrative paragraph) and `stageGroup` (print the AJCC stage group under the pTNM) are conventional on every cancer template.
- `showIf` numeric `min` / `max` on number fields (e.g. extranodal extension only when `nodesPositive` ≥ 1).

## Snippets

`snippets: [{ id, label, text, auto?: { field, is | not | truthy } | { flag } }]`. Each is offered as a Comments checkbox for the case; `auto` pre-ticks it when any part matches the field rule, or when the generator's `flags(parts, ctx)` export returns the named flag for the case (gastric: `hpNoIm`, `hpWithIm`, `imIncompleteAlone`, `olgaHigh`). Generators may also export `summary(parts, ctx)` for a case-level line under the diagnosis (gastric OLGA / OLGIM stage). `text` may use `{parts}` for the part letters. Active snippets and the free-text comment print as a COMMENT block after the diagnosis.

## Field reference photos

Any field may carry `reference` to give the pathologist a side-by-side visual key next to the pick-list:

```json
"reference": {
  "title": "Complete vs incomplete intestinal metaplasia",
  "intro": "one-line guidance",
  "groups": [
    { "heading": "Complete (type I)", "points": ["criterion", "..."],
      "images": [{ "src": "assets/reference/gastric/im_complete_he.jpg", "caption": "...", "credit": "Author et al., Journal Year, Fig 4A (cropped)", "license": "CC BY 4.0", "url": "https://doi.org/..." }] }
  ],
  "note": "licence footnote"
}
```

The app renders a "Compare photos" toggle beside the control; the panel spans the field row with one column per group. Images live under `assets/reference/<organ>/` (≤ 900 px, JPEG) and must be openly licensed (CC BY / CC BY-SA / CC0) with the credit, licence and source URL recorded — `tests/reference.test.js` checks that every image file exists and carries all four. Never use AI-generated histology.
