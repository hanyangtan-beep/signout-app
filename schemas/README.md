# schemas

One JSON file per template. Keys: `id`, `version`, `name`, `shortName`, `organ`, `specimenNoun`, `maxParts`, `defaultParts`, `generator`, `style`, `caseFields`, `options`, `partDefaults`, `fields`, `example`.

Field types: `text`, `textarea`, `number` (`min`, `step`, `suffix`), `checkbox`, `select` / `grade` (`options`, `optionLabels`, `optionsByField`, `showIf`, `defaultForFirstPart`), `multiselect` (array value; `options`, `exclusive: [option]` clears the others when ticked, `default: []`).

`showIf: { field, is | not | truthy | min | max }` — for multiselect fields `is` means "contains any of", `not` "contains none of", `truthy` "at least one ticked", `min` / `max` count the ticked options.

Optional keys: `options[]` case-level switches (`{id, label, default}`; read by the generator through `ctx.options`); `presets[]` one-click part sets (`{id, label, help, caseTitle, parts: [{values}]}` — the Presets row in the case card replaces all parts, see the gastric Sydney protocol).

Templates: `gastric_biopsy`, `colonic_polyp`, `prostate_biopsy`, `ibd_biopsy`, `oesophageal_biopsy`, `frozen_section`, `breast_biopsy`, `duodenal_biopsy`, `cervical_biopsy`, `endometrial_biopsy`, `cervical_excision` (LEEP), `lung_biopsy`, and the Phase 4b benign resections `lymph_node`, `placenta`, `gallbladder`, `thyroid_benign`, `parathyroid`, `appendix`, `uterus_benign`, `ovarian_cyst`, `skin_cyst`, `skin_excision`, `breast_excision`, `turp`, `turbt`, `tonsils`, `soft_tissue_benign` (breast is generated by `node scripts/build-breast-schema.mjs`, which pulls the biomarker fields from `generators/breast_biomarkers.js` — edit the script, not the JSON).

Template metadata (Phase 4d, required — `scripts/build-manifest.mjs` refuses a schema without them): `system` (GI, Hepatobiliary, GU, Gynae, Breast, Thoracic, Head and neck, Skin, Cardiovascular, Lymphoid, Soft tissue, Endocrine, Frozen), `kind` (`biopsy` / `benign resection` / `cancer resection` / `frozen`), `shortName` as "Organ · procedure" (`Cervix · LEEP / cone`), `label` (the short header word — never a bare procedure or lesion name such as "Biopsy" or "Polyp"), `rank` (header order within the Small biopsy row; lower = more frequent; default 100), `aliases` (palette search terms — abbreviations, eponyms, key findings). After editing metadata run `node scripts/build-manifest.mjs` (also done by `npm run build`); `tests/picker.test.js` fails if the committed manifest is stale. Optional: `snippets[]`, `options[]`, `presets[]`.

## Benign resections (Phase 4b)

Resection templates carry a **Macroscopy** field group (`"group": "Macroscopy"` on each consecutive macroscopic field — the part card renders them in one collapsible fieldset whose open/closed state is remembered) and two extra generator exports: `macro(part, ctx)` → the `(A) Received in formalin is a …` paragraph (MACROSCOPIC DESCRIPTION block) and `blockKey(part, ctx)` → one `(A) (1) Cystic duct margin. (2) Body. (3) Fundus.` line (BLOCK KEY block, printed after the macro and merged above the typed block key in the Google Doc). Both return `''` when the case option `macro` is off. The engine drops the `(A) ` prefix for single-part cases, so the printed block key matches the house `(1) … (2) …` form. Building conventions, wording rules and the test checklist are in `docs/phase4b-brief.md`.

## Snippets

`snippets: [{ id, label, text, auto?: { field, is | not | truthy } | { flag } }]`. Each is offered as a Comments checkbox for the case; `auto` pre-ticks it when any part matches the field rule, or when the generator's `flags(parts, ctx)` export returns the named flag for the case (gastric: `hpNoIm`, `hpWithIm`, `imIncompleteAlone`, `olgaHigh`). Generators may also export `summary(parts, ctx)` for a case-level line under the diagnosis (gastric OLGA / OLGIM stage). `text` may use `{parts}` for the part letters. Active snippets and the free-text comment print as a COMMENT block after the diagnosis.

## Field reference photos

Any field may carry `reference` to give the pathologist a side-by-side visual key next to the pick-list:

```json
"reference": {
  "title": "Complete vs incomplete intestinal metaplasia",
  "intro": "one-line guidance",
  "groups": [
    { "heading": "Complete (type I)", "points": ["criterion", "..."],
      "images": [{ "src": "assets/reference/gastric/im_complete_he.jpg", "caption": "...", "credit": "Author et al., Journal Year, Fig 4A (cropped)", "license": "CC BY 4.0", "url": "https://doi.org/..." }] }
  ],
  "note": "licence footnote"
}
```

The app renders a "Compare photos" toggle beside the control; the panel spans the field row with one column per group. Images live under `assets/reference/<organ>/` (≤ 900 px, JPEG) and must be openly licensed (CC BY / CC BY-SA / CC0) with the credit, licence and source URL recorded — `tests/reference.test.js` checks that every image file exists and carries all four. Never use AI-generated histology.
